# Анализ логов веб-сервера (Занятие 2)

Лог: `access.log` (nginx, тестовый датасет), формат:
`IP - - [дата] "МЕТОД /путь HTTP/1.1" КОД РАЗМЕР "referer" "user-agent"`

**1. Сколько запросов вернули код 404?**
```bash

```

**7. Суммарный объём отданных данных**
```bash
awk '{sum += $10} END {print sum/1024/1024 " MB"}' access.log
```
Результат: **~32367.4 MB (~31.6 ГБ)**

**8. Топ-5 URL с ошибками 4xx/5xx**
```bash
awk '$9 ~ /^[45]/ {print $7}' access.log | sort | uniq -c | sort -rn | head -5
```
Результат:
20797 /downloads/product_1
13121 /downloads/product_2

**9. Анонимизация IP в логе**
```bash
sed -E 's/^[0-9]+\.[0-9]+\.[0-9]+\.[0-9]+/X.X.X.X/' access.log > access_anon.log
```
Зачем: IP — персональные данные (152-ФЗ/GDPR), логи анонимизируют перед передачей во внешние системы/коллегам, чтобы не слить личные данные пользователей.

**10. Топ-5 самых больших файлов в `/var`**
```bash
find /var -type f -exec du -h {} \; 2>/dev/null | sort -rh | head -5
```
Результат: топ — кэш `apt` (`archive.ubuntu.com` package lists, `pkgcache.bin`, `srcpkgcache.bin`), 56-70 МБ каждый.

## Инцидент: «grep пишет пустой файл, хотя ошибки есть»

Три причины:
1. **Регистр** — лог содержит `error`, а не `ERROR`. Проверка: `grep -i error app.log`.
2. **Ошибка доступа к файлу** (неверный путь/нет прав) — `grep` пишет в stderr, а не в файл. Проверка: `grep ERROR app.log > errors.txt; echo $?`.
3. **Ротация логов** — актуальные ошибки уже в `app.log.1`. Проверка: `ls -la app.log*`.
